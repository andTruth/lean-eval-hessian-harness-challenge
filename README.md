# Lean Eval Hessian Harness Challenge

Prove the [Lean Eval Hessian estimate](https://lean-lang.org/eval/problems/annals_hessian_estimates/)
with a generic AI harness of your choice
in **under 5 hours** for **at most $20 on OpenRouter**. Our result was approximately **$9 in 3 hours**.
We are especially interested in replicating or beating that result without fine-tunned solution.

Use Lean **4.35.0**. Prove `solution : Problem.Statement` in `Solution.lean`
against the supplied [definitions](problem/Problem.lean).

## Rules

- Use models released before **2026-11-01**, such as `claude-opus-5.5`, `gpt-6.1-sol`, `kimi-k3.1-pro`.
- Time includes model calls, tools, retries, compilation and verification. Preinstall dependencies in your image.
- Harness, prompts and custom tools should have max **100 KB** total, don't overenginner it.
- Generated by harness Lean proof sources should have max **1 MB**.
- Keep the harness generic: no hints, proof fragments or strategies for this specific problem.
- Run autonomously without internet access except OpenRouter inference. Do not use earlier solutions or human guidance.
- Keep the statement and definitions unchanged. No `sorry`, extra axioms, `native_decide` or verification bypasses.

Use any harness you want, eg. Codex, Claude Code, oh-my-pi, create generic local tools or local MCP servers.
We will be later testing created harness on 2 other problems with similar difficulity from lean-eval.

## Codex example

Repository comes with ready to use Docker image which can work as a base for your own image.
The prebuilt amd64/arm64 image includes stock **Codex 0.166.0**, Lean, Mathlib and its compiled dependencies.
No dependency installation or cache downloads are needed when proving.
To run the example harness, set `.env`:

This examples costs around **$50** to run and takes around **2 hours**.

```dotenv
OPENROUTER_API_KEY=your-key
MODEL=openai/gpt-6.1-sol
```

In VS Code choose **Reopen in Container**, then run `./run.sh` from the mounted repository.

Or you can run it without devcontainer just with a docker command:

```bash
docker run -it --init --mount "type=bind,source=$PWD,target=/workspace" \
  ghcr.io/andtruth/lean-eval-hessian-harness-challenge:latest ./run.sh
```

- Use a fresh container per run.
- The script reports elapsed time and spending.
- Edits, scratch files and logs persist in the mounted checkout.
- Preinstalled dependencies live in `/opt`.
- All output streams to the terminal and `run.log`.
- `run.log` is cleared at startup and appended across follow-ups.
- The runner uses high reasoning effort and resumes the same session after a failed audit.
- Active turns may finish beyond five hours or $20 for analysis.
- No new follow-up starts after five hours.
- Edit `prompt.txt` for initial instructions and `prompt-follup.txt` for continuations.
- Each continuation includes the latest verification errors.
- Proof work stays in `problem/`; use `scratch/` there for temporary files.
- Git worktrees are available.
